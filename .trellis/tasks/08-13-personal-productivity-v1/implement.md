# 个人效率与个人财务管理应用 V1 — 首期实施计划

> **状态：规划中，等待用户批准。**  
> 前置文档：[`prd.md`](./prd.md)（产品范围与验收）和 [`design.md`](./design.md)（高层架构与跨域边界）。本文件只定义首期 V1 的高层实施顺序；每个实施任务启动前仍须完成其自身的详细方案、接口合同、数据迁移、测试设计与必要的 UX/UI 设计。这不是首周排期，也不代表当前已经开始写代码。

## 1. 实施原则

1. **先证明“可靠记录”，再加智能。** AI、语音、统计和小组件都不能成为手动记录、同步或恢复的单点依赖。
2. **三项能力同等重要，但共享地基按依赖顺序建设。** 先完成账户、加密、同步和收件箱，再并行完善待办、记账、笔记；这不是降低其中任一功能的重要性。
3. **每个阶段可验证、可停下。** 阶段完成必须有明确演示、自动化测试和回滚形态；不得堆积到最后统一集成。
4. **先把隐私规则写进代码结构和测试。** 不把“不要记录正文/音频”停留在口头约定。
5. **Alpha 前不追求“功能全”。** 只交付 PRD 已列闭环，所有扩展项进入后续候选池。

## 3. 首个可验证执行任务（建议先做）

### T01：建立“受邀用户的可靠文本收件箱”纵向切片

**目的：**先验证产品中最关键、又同时服务于待办/记账/笔记三项能力的基础事实：一个受邀用户能够在 Android 离线安全记下原文，联网后同步到服务端，并在 Web 的待确认收件箱中看到同一条原文。该任务**不**做 AI、语音、自动分类、统计、小组件或三类正式业务表单。

这比先做漂亮首页或先接大模型更有价值：若这个切片不可靠，后面所有“智能”功能都会放大数据丢失风险。

### T01 范围

1. 建立 `apps/android`、`apps/web`、`services/api`、`contracts/openapi` 的最小可构建工程和本地开发环境；
2. 后端实现受邀注册/邮箱验证（开发环境可用安全的本地邮件捕获器）、登录、会话与用户隔离；
3. 定义并实现 `Capture` 的最小数据模型：加密原文、`pending` 状态、创建/更新时间、来源为 `typed`；
4. Android 支持离线创建一条文本 Capture，写入本地工作副本和 `pending_operations`，并清晰显示“待同步/已同步/失败可重试”；
5. 实现最小 `POST /captures`、`GET /captures`、`POST /sync/push`、`GET /sync/pull`；
6. Web 支持登录后查看自己的待确认收件箱原文；
7. 写入最小审计/脱敏日志和关联 ID；禁止正文、令牌、密码写入日志。

### T01 不包含

- 待办、账目、笔记正式资源和编辑；
- AI 整理、偏好、音频或语音转写；
- 回收站、周回顾、统计、小组件、管理员日志 UI；
- 多设备并发冲突 UI（只需协议预留 revision / idempotency）。

### T01 完成标准

- [ ] 本地开发环境可一条命令启动 API、PostgreSQL、Web 及本地邮件捕获；Android 模拟器可连接开发 API。
- [ ] 一张一次性邀请码只能创建一个已验证账户；另一个账号无法读取该账户 Capture。
- [ ] 断网状态下 Android 创建 Capture 后，不重启应用也不丢失；恢复网络后同步到 Web。
- [ ] 重复同步同一 `operationId` 不生成重复 Capture。
- [ ] API、Android 本地库、日志和错误响应中都没有 Capture 原文、密码或令牌的意外输出。
- [ ] Go 单元/集成测试、Android 本地持久化测试、Web API 视图测试、OpenAPI 契约检查全部通过。

### T01 退出决策

只有 T01 被真实验证后，才能大规模开始后续业务域。若失败，应优先修复认证、加密、本地持久化、同步幂等或日志脱敏；不得用 AI 功能掩盖地基问题。

## 4. V1 分阶段实施任务图

```text
T01 可靠文本收件箱纵向切片
  ├─ T02 共享安全、同步与回收地基
  │    ├─ T03 待办 + 以后想做 + 今日重点
  │    ├─ T04 记账 + 分类 + 基础统计
  │    └─ T05 笔记 + 检索 + 笔记转待办
  ├─ T06 Android 日常行动体验 + 小组件
  ├─ T07 Web 整理、周回顾与财务工作台
  ├─ T08 智能文本整理 + 偏好 + 配额
  ├─ T09 Android 在线语音转写
  ├─ T10 账号删除、运营后台、受控可观测性
  └─ T11 Alpha 加固、演练与发布准备
```

T03/T04/T05 可以在 T02 稳定后分开实施、分开验收；T06/T07 可随各业务 API 逐步推进，但最终集成以 T07、T08、T09、T10、T11 顺序收口。

### T02：共享安全、同步、回收与契约地基

**依赖：**T01 通过。  
**目标：**把“可恢复的多设备个人数据”做成三项业务都可复用的能力。

**范围：**

- 用户密钥包裹、字段 AEAD 加解密、key version、加密检索令牌基线；
- 统一资源 revision、幂等操作、change log、sync cursor、墓碑与显式冲突记录；
- 统一 30 天回收站、恢复和立即永久删除框架；
- OpenAPI 枚举、错误响应、分页和契约测试；
- Android `Room + pending_operations + WorkManager` 同步引擎的通用化；
- 认证限流、设备会话撤销、基础审计事件；
- 迁移、备份/恢复演练脚本雏形。

**完成标准：**

- [ ] 不同用户、不同字段或不同资源之间交换密文会因 AAD 校验失败而不能解密。
- [ ] 断网更新、重复 push、pull 重放、删除墓碑和恢复都不会产生重复或复活的旧数据。
- [ ] 同一实体的并发敏感修改返回可解析冲突，保留两个版本，绝不静默覆盖。
- [ ] 任一业务域接入统一回收站只需实现资源适配，不重复发明删除逻辑。
- [ ] schema 变更通过 OpenAPI contract tests；数据库迁移能在空库和前一版本库升级。

### T03：待办、以后想做、今日重点与提醒

**依赖：**T02。  
**范围：**

- 待办 CRUD、完成/重新打开、放弃、计划/截止时间、三档优先级；
- “以后想做”状态和透明推荐规则；
- 今日重点排序与显示原因；
- 回顾窗口、一次温和提醒、跳过/自动顺延、下周 1–3 件选择；
- Android 和 Web 的基础待办操作；提醒时段/关闭设置。

**完成标准：**

- [ ] 固定时钟和 fixture 下，今日排序严格符合 `TODO-04`。
- [ ] “以后想做”不会被任何后台任务自动排期或自动催促；所有推荐有可读原因。
- [ ] 用户能完成一次可跳过的周回顾，并让推进/保留/减少出现/不再需要影响后续推荐。
- [ ] 两端修改同一待办时间时显式产生冲突，不以最后写入覆盖。

### T04：记账、分类与可信收支回顾

**依赖：**T02。  
**范围：**

- 账户基础货币设置、内置/自定义分类、账目 CRUD、可选支付方式；
- 最小货币单位金额验证和精确显示；
- 按日/周/月/分类的已记录收入、支出和结余；
- 周回顾收支摘要和透明规则的“值得查看的收支变化”；
- Android 快速记一笔与 Web 筛选/汇总。

**完成标准：**

- [ ] 金额计算在边界金额、负向输入、四舍五入显示和汇总场景下精确；测试中不存在浮点金额真相。
- [ ] 所有汇总文案和接口字段只描述已记录账目。
- [ ] 支付方式不会生成账户余额、转账或对账功能。
- [ ] 数据不足时不生成变化提示；提示包含对比范围和触发规则，不包含价值判断词。

### T05：笔记、找回与笔记转待办

**依赖：**T02。  
**范围：**

- 笔记原文 CRUD、时间线、类型、轻量标签、收藏、稍后回顾；
- 加密关键词检索令牌 + 服务端解密回验、时间/类型/状态筛选；
- 从笔记创建新的待办/以后想做并建立双向关联；
- Android 和 Web 的笔记读写、找回与删除恢复。

**完成标准：**

- [ ] 对任何保存、同步、检索和关联创建操作，笔记 `body` 字节序列只有用户编辑时才改变；回归测试证明 AI/系统路径不改写正文。
- [ ] 关键词搜索对同用户命中后回验正确，不返回其他用户记录。
- [ ] 删除或永久清理笔记时同步清理检索令牌与关联规则；恢复时关系按规则恢复。
- [ ] 由笔记创建待办不删除、覆盖或移动原笔记正文。

### T06：Android 日常行动体验与小组件

**依赖：**T03、T04，且 T05 的基础入口可用。  
**范围：**

- 今日概览：快速入口、重点待办、今日进度、基础收支和明显同步状态；
- 记一笔/加待办/写笔记的手动优先表单；
- 离线草稿、失败重试、冲突入口、回收站入口；
- 一个预设小组件模板、允许内容设置、首次添加隐私引导、默认隐藏标题/金额；
- 无障碍基础、通知权限与提醒时段处理。

**完成标准：**

- [ ] Android 首页不需要 AI 成功即可完成三类手动记录。
- [ ] 小组件默认不泄露待办标题或财务金额；用户首次启用详情前会看到明确隐私说明。
- [ ] 离线创建/编辑/删除的状态始终可见，失败可以人工重试。
- [ ] TalkBack 可读核心控件，横竖屏/字体放大不遮蔽关键确认和删除操作。

### T07：Web 整理、周回顾和财务工作台

**依赖：**T03、T04、T05。  
**范围：**

- 用户端数据工作台而非 Android 镜像：待确认收件箱、待办/以后想做、账目筛选与统计、笔记搜索、周回顾、回收站、账户设置；
- 桌面批量整理、筛选和冲突处理 UI；
- API 错误、会话失效和并发冲突的清晰反馈。

**完成标准：**

- [ ] 用户可以通过 Web 完成 PRD 要求的一次周回顾和一次收支回顾。
- [ ] 用户在 Android 创建的三类内容可在 Web 找到、编辑、删除、恢复；所有写入仍遵循 revision/幂等规则。
- [ ] 管理员路由与普通用户路由权限隔离，普通用户不会看到后台数据。
- [ ] Playwright 覆盖登录、搜索筛选、回顾、回收站恢复和冲突处理主流程。

### T08：智能文本整理、待确认收件箱与个性化偏好

**依赖：**T03、T04、T05、T07。  
**范围：**

- OpenAI 文本整理 provider、受限 JSON Schema、服务端 schema/业务校验；
- `记一笔`、`加待办`字段建议，智能快速记录的类型建议和待确认收件箱转换；
- 用户主动请求的笔记元信息建议；
- 结构化偏好规则、用户查看/修改/关闭/清除；
- 单用户日限额、平台总上限、告警、紧急关闭、确认/修改/拒绝指标；
- fake provider、失败诊断快照（不含正文）。

**完成标准：**

- [ ] 模型无法直接写入正式资源；每个正式结果都有用户确认、编辑或手动创建证据。
- [ ] 不确定、超时、限流、无效 JSON、违反业务约束的输出都保留原文并落到手动/待确认路径。
- [ ] 笔记在用户未主动请求时零模型调用；请求时模型只收到该笔当前笔记和最小必要偏好。
- [ ] 关闭 AI、耗尽个人额度或全局紧急关闭后，三项功能手动路径和同步完整可用。
- [ ] 日志/诊断快照测试验证禁止字段不存在；诊断快照 7 天自动清理且查看写审计。

### T09：Android 在线语音转写

**依赖：**T06、T08 的外部服务治理基础（但转写开关独立）。  
**范围：**

- Android 录音、私有加密临时文件、24 小时状态机、12 小时/1 小时提示、清理；
- `POST /voice/transcriptions` 请求内音频转发、MIME/大小/时长/速率校验、通过 `TranscriptionProvider` 的单一 OpenAI 转写适配器；
- 普通话/英语 language hint、可编辑转写文本、转入笔记或智能/手动入口；
- 失败重试、取消、放弃、到期不可恢复删除和不含正文的状态提示。

**完成标准：**

- [ ] 转写成功后先展示可编辑文本；未确认前不创建正式笔记、待办或账目。
- [ ] 服务端、对象存储、数据库、日志和诊断中均不存在音频持久化副本。
- [ ] 转写失败时 Android 可在 24 小时内重试或改手动文本；成功、取消、放弃、到期均删除本地音频和密钥材料。
- [ ] 到期语音草稿不能从 30 天回收站恢复；只留无正文的“已过期删除”状态。
- [ ] 通过代理/服务器集成测试验证请求中断、提供商超时和 MIME 伪造不会留下音频文件或日志内容。

### T10：账号删除、运营后台与受控可观测性

**依赖：**T01–T09 的基础能力；可与后期 UI 整合部分并行，但 Alpha 前必须完成。  
**范围：**

- 管理员登录、邀请码管理、用户停用/恢复、AI 用量/效果、删除申请、管理员审计；
- 脱敏运行日志与 AI 错误日志查询、诊断快照权限/审计；
- 用户账号删除申请、人工受理、立即停用/会话撤销/同步和 AI 阻断、30 天撤销与到期清理；
- 30 天回收站、7 天诊断、邀请码/会话/审计等保留任务的定时执行和失败告警。

**完成标准：**

- [ ] 一次性邀请码、账号停用/恢复和管理员敏感操作均有完整、无正文的审计轨迹。
- [ ] 管理后台默认无法浏览用户笔记、待办、账目备注或完整模型输入输出。
- [ ] 账号删除受理后，所有会话立即失效，客户端同步/AI 请求被拒绝；撤销期内可按规则恢复，到期后清理可识别数据和 DEK 包裹材料。
- [ ] 管理员只能在显式权限下查看合规的诊断快照，所有查看被审计；过期任务可重试且幂等。

### T11：Alpha 加固、演练与发布准备

**依赖：**T01–T10。  
**范围：**

- 端到端测试矩阵、真实设备验证、数据库备份恢复演练、密钥轮换演练、负载/限流验证、故障注入；
- OpenAI 文本整理/转写、邮件、KMS、备份和日志的实际部署配置、成本阈值、AI/语音紧急开关；
- 用户隐私说明、数据删除与备份残留说明、Alpha 邀请/反馈/支持流程、管理员 runbook；
- 3–5 位 Alpha 用户上线、14 天观测看板和扩容/暂停检查清单。

**完成标准：**

- [ ] 无不可恢复内容丢失、跨账号数据泄露、静默篡改或关键同步不可见失败的已知阻断问题。
- [ ] 从备份恢复到隔离环境的演练成功，且不会把恢复数据错误暴露给其他账号/环境。
- [ ] AI/语音提供商不可用、网络断开、数据库短暂不可用、会话失效和冲突均有可演示的安全降级。
- [ ] 已发布可执行的删除/备份、故障响应、密钥轮换和管理员权限 runbook。
- [ ] Alpha 首批邀请、反馈收集、成本监控和扩容决策人明确，且 AI/语音有紧急关闭验证。

## 5. API 与数据实施顺序

为避免 Android、Web 和后端各自猜测规则，按以下顺序交付契约：

1. `identity.yaml`：邀请、注册、验证、会话、账户/设备、统一错误；
2. `capture-sync.yaml`：Capture、操作幂等、cursor、revision、冲突；
3. `todo.yaml`、`ledger.yaml`、`note.yaml`：三项正式资源与回收站；
4. `review-dashboard.yaml`：今日重点、周回顾、统计、收支变化提示；
5. `ai.yaml`、`voice.yaml`：建议草稿、配额、转写、可恢复错误；
6. `admin.yaml`：后台最小 DTO、日志、审计、删除申请。

每份 schema 合并前必须：

- 给出成功、验证失败、未认证、无权、冲突、限流和外部依赖失败示例；
- 标出哪些字段加密、哪些字段可索引、哪些字段永不写日志；
- 由 Go handler contract test 和 Web/Android DTO 编译检查共同验证；
- 明确版本兼容策略，禁止客户端自行解释未定义字段。

## 6. 测试策略与质量门

### 6.1 测试金字塔

| 层级 | 重点 | 代表性验证 |
| --- | --- | --- |
| 领域单元测试 | 纯规则、金额、排序、回顾、保留期、状态机 | 今日排序、收支变化、语音 24 小时过期、邀请码一次性使用。 |
| 应用服务测试 | 授权、幂等、加密、AI 降级、删除/恢复 | 不同 user scope、同一操作重放、AI 无效 JSON 保留原文。 |
| 数据库集成测试 | migrations、约束、事务、cursor、冲突 | 真实 PostgreSQL 测试容器；并发 update 不静默覆盖。 |
| 契约测试 | OpenAPI 与客户端 DTO | schema 示例、错误码、枚举、分页、金额字符串/整数格式。 |
| Android 测试 | ViewModel、Room、同步队列、临时音频清理 | 断网重启、WorkManager 重试、Keystore/加密失败降级、widget 隐私默认值。 |
| Web 测试 | 业务组件、状态、路由、E2E | 登录、筛选、回顾、冲突、回收站、管理员无正文列表。 |
| 端到端/演练 | 跨端完整闭环、安全和运维 | Android 离线记录 → 同步 → Web 整理/回顾 → Android 行动；备份恢复；提供商故障。 |

### 6.2 必须固定为自动化回归的高风险场景

1. 跨用户猜测 ID、篡改请求 user ID、管理员越权读取正文；
2. 同一同步操作重发、网络中断、客户端崩溃、cursor 重放、删除墓碑；
3. 笔记正文通过任何系统/AI/同步路径被改变；
4. 金额浮点误差、时区跨日/跨周、分类删除/停用后的历史统计；
5. AI 无效输出、超时、限流、配额耗尽、紧急关闭和用户关闭；
6. 音频上传失败、中断、MIME 伪造、转写失败、24 小时过期、服务端无残留；
7. 30 天回收站、立即永久删除、账号删除停用/撤销/到期；
8. 日志、审计、APM、测试失败输出中敏感正文/令牌/音频泄漏；
9. 小组件默认状态不展示标题和金额；
10. 后台诊断快照权限、审计和 7 天清理。

### 6.3 每次合并的最低质量门

```text
1. 格式化 + 静态检查 + 编译通过
2. 变更模块的单元测试与真实 PostgreSQL 集成测试通过
3. OpenAPI contract / client DTO 检查通过
4. 安全日志扫描：禁止字段不被输出
5. 迁移可从空库和前一 schema 升级；有回滚或兼容说明
6. UI 变更具备核心交互、空态、加载、网络失败、权限失败和无障碍检查
7. 影响同步/加密/删除/AI/语音时，补充相应端到端或故障注入测试
```

### 6.4 Alpha 发布门

T11 后，按以下门槛决定是否发首批邀请码，而不是仅以“功能页面都完成”判断：

- 三项功能均可通过手动路径记录、同步、回顾、删除和恢复；
- Android 离线记录、Web 整理和 Android 回到今日行动闭环已在真实设备验证；
- 最小安全、日志脱敏、语音无存档、同步冲突和账号/回收站保留期测试完成；
- AI 和语音均可独立关闭而不破坏手动路径；
- 备份恢复、账号删除、管理员权限和故障应对已有演练记录；
- Alpha 成本预算、日上限、全局上限、告警、支持方式和暂停扩容条件已经写入 runbook。
